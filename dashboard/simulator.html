Dispute simulator

A fact pattern walks through three stages: pick a claim type, fill in the facts each applicable rule needs, and the simulator runs every rule against the same fact pattern and aggregates the result. Each rule is encoded in rules/ as a Catala module; the inputs are auto-generated from catala json-schema; the predicates run server-side via catala interpret -F json. The dispositive question — "if filed today at this tribunal, what does the rule say?" — is computed mechanically.

How to use this page

Predict the outcome of a whole dispute, not just one rule

The Playground runs one rule. This page runs every rule that applies to a given claim type at a given tribunal, against the same fact pattern. Useful when the answer depends on multiple rules talking to each other — for example, a fresh-evidence application that has to clear the Ladd v Marshall test and the indemnity-costs rule.

Three steps

  1. Pick a claim type (e.g. "fresh-evidence application", "summary judgment") and a tribunal (DIFC / ADGM / SICC). The rules registered for that combination light up below.
  2. Fill in the facts, once. Each rule's required inputs appear in its own panel. Defaults are pre-seeded.
  3. Click "Run all rules". Each rule's verdict is shown alongside an aggregated predicted disposition with a confidence score.

What the output means

  • Per-rule verdict — what each rule said in isolation (admissible, costs awarded, claim succeeds, etc.).
  • Predicted disposition — the simulator's aggregated reading of how those verdicts compose. Some rules act as gates (must pass before others apply); some are independent.
  • Confidence — a heuristic score reflecting how decisive the rule chain is. High confidence = unanimous outcome. Low confidence = contradictory rules or missing inputs.
